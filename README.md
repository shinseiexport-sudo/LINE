# 店舗LINE運用システム — 導入手順書

グループ管理・店舗管理・LINE公式アカウント接続・共通顧客台帳までを動かすための手順です。
プログラミングの知識は不要です。すべてコピペで設置できます。

## 第1段階の設置手順（初回はこちらから）

## 手順0: そろえるもの

- システム管理者用のGoogleアカウント
- LINE公式アカウントと、LINE DevelopersコンソールのMessaging APIチャネル（未作成の場合は付録A）

## 手順1: スプレッドシートを用意する

1. ブラウザで https://sheets.new を開く（新規スプレッドシートが作成されます）
2. 左上の「無題のスプレッドシート」をクリックして「店舗LINE運用_（グループ名）」に変更
3. このファイルが「1グループ分のデータベース」になります

## 手順2: GASプロジェクトを開く

1. スプレッドシート上部のメニューで「拡張機能」→「Apps Script」
2. 新しいタブでスクリプトエディタが開きます

## 手順3: ファイルを作成してコードを貼り付ける

1. エディタ左上の「ファイル」（＋アイコン）→「スクリプト」を9回繰り返し、表の9つのスクリプトファイルを同じ名前で作る
   （例：「Code」「Config」「Bootstrap」「Utils」「GroupService」「StoreService」「LineService」「Webhook」「CustomerService」）
2. 同じく「ファイル」（＋アイコン）→「HTML」を3つ作る（「Index」「Styles」「Script」）
3. 各ファイルを開き、配布された同じ名前のファイルの中身をすべて貼り付ける
   - HTMLファイルには最初から `<style>` などが入っているので、すべて消してから貼り付ける
4. `Ctrl + S` で保存
   - 最初からある「appsscript」というファイルはそのまま残してOK

## 手順4: エディタから動作確認する

1. エディタ上部の関数選択（「myFunction」と表示されているプルダウン）で「debugCheck」を選ぶ
2. 右隣の「実行」を押す
3. 初回のみ「承認が必要です」と表示されるので:
   - ①「権限を確認」→ 自分のアカウントを選択
   - ②「このアプリは確認されていません」と出たら左下の「詳細」→「（プロジェクト名）（安全でないページ）に移動」
   - ③「許可」
4. 実行ログに「シート初期化: OK」と出て、スプレッドシートに次の9枚のシートが自動作成されていれば成功
   - GroupSettings / Stores / LineSettings / Customers / Reservations / VisitHistory / Campaigns / MessageLogs / CouponLogs

## 手順5: Webアプリとして公開する

1. エディタ右上の「デプロイ」→「新しいデプロイ」
2. 歯車アイコン →「ウェブアプリ」を選び、次のように設定:
   - 説明: 第2段階
   - 実行ユーザー: 自分
   - アクセスできるユーザー: **自分のみ**（管理画面は必ず「自分のみ」）
3. 「デプロイ」→ 表示された「ウェブアプリ」のURLをコピー
4. そのURLをブラウザで開くと管理画面が表示されます

## 手順6: 管理画面で初期設定する

1. 「① グループ設定」タブでグループ名・管理者メールアドレスを入力して「保存する」
2. 「② 店舗管理」タブで「＋ 店舗を追加」から店舗を登録（登録後は「編集」「利用停止」「稼働へ戻す」ができます）

## 手順7: LINE公式アカウントを接続する

やることは大きく2つです。

- **【LINE側】** LINE Developersコンソールで「チャネルID」と「トークン」の2つを取得する → 手順7-A〜7-C
- **【管理画面側】** 取得した2つを管理画面に貼り付けて「保存して接続確認」を押す → 手順7-D〜7-E

> **用語の整理（最初に読んでください）**
>
> - **チャネル** … LINE公式アカウントをシステムから動かすための「通信口」。設定はLINE Developersコンソールで行います
> - **チャネルID** … その通信口を識別するだけの数字。公開してよい情報です
> - **チャネルアクセストークン（長期）** … 通信口を使うための「合言葉」。**この文字列を知っている人は、あなたのLINE公式アカウントから自由にメッセージを送れます。**絶対に他人に見せないこと（画面を人に見せるときも注意）

### 7-A. LINE Developersコンソールでチャネルを開く

1. ブラウザで **https://developers.line.biz/console/** を開き、LINE公式アカウントで使っているLINEアカウントでログインします
2. 画面に並んでいる「プロバイダー」（グループ名などを登録した枠）をクリックします
3. チャネルの一覧から、接続したいチャネル（Messaging APIチャネル）の名前をクリックします
   - チャネルが1つも無い場合は、先に付録Aを行ってください

### 7-B. チャネルIDを控える

1. 画面上部のタブから **「基本設定」** をクリックします
2. 「チャネル基本情報」の中に **「チャネルID」** という項目があります。数字（例: `1234567890`）が表示されます
3. その数字をコピーして、メモ帳などに貼り付けておきます
   - これが管理画面に入力する「チャネルID」です

### 7-C. チャネルアクセストークン（長期）を発行してコピーする

1. 画面上部のタブから **「Messaging API設定」** をクリックします
2. ページの下のほうにある **「チャネルアクセストークン（長期）」** という項目を探します
3. 「発行」ボタンを押すと、100文字以上の長い文字列が表示されます
   - すでに発行済みで文字列が表示されている場合は、それをそのまま使えます
   - 文字列が見当たらない場合は「再発行」を押してください（古いトークンは自動的に無効になります）
4. 文字列全体をコピーして、メモ帳などに貼り付けておきます

### 7-D. 管理画面に入力して接続確認する

1. 手順5でコピーしたWebアプリのURLをブラウザで開きます
2. 上部のタブ **「③ LINE接続」** をクリックします
3. 下のほうの「トークンの保存と接続確認」カードで、2つの入力欄に次を入力します
   - 「チャネルID」→ 7-Bで控えた数字
   - 「チャネルアクセストークン（長期）」→ 7-Cでコピーした文字列
4. **「保存して接続確認」** ボタンを押します
   - このボタン1つで「トークンの保存」と「LINEへの接続テスト」を両方行います。押して数秒待ちます

### 7-E. 成功したか確認する

- ページ上の「接続状態」カードを見ます
  - **成功**： 「接続済み」（緑のバッジ）になり、ボット表示名や基本IDが表示されます
  - **失敗**： 「エラー（要再設定）」というバッジが出ます → その下の「接続できないときは」カードの対処に従います。**ほとんどはトークンの貼り間違い**なので、7-Cの「再発行」からやり直すと解決します

> **補足: トークンはどこに保存されるのか（手順ではなく説明です）**
>
> - 入力したトークンは、スプレッドシートのセルにも、管理画面のどこにも表示されません
> - GASの「スクリプトプロパティ」という、GASプロジェクトの管理者だけが確認できる保管場所に保存されます
> - そのため、保存後に画面へトークンは出てきません。「接続状態： 接続済み」と表示されることが、保存できた証拠です
> - 貼り直すときは、同じフォームに新しいトークンを入力して保存すれば上書きされます

## 第2段階の設置手順（すでに第1段階を設置済みの場合）

## 手順8: 第2段階のファイルをGASに入れる

1. 手順2と同じGASプロジェクトを開く
2. **入れ替え**（既存ファイルを開いて上書き）: `Config.gs` `Bootstrap.gs` `Code.gs` `Index.html` `Styles.html` `Script.html`
3. **新規追加**（「ファイル」＋ →「スクリプト」で作ってから貼り付け）: `Webhook.gs` `CustomerService.gs`
4. `Ctrl + S` で保存
5. 手順9のやり方で「新しいバージョン」として再デプロイ（URLは変わりません）
6. 管理画面を開き直すと「④ 顧客台帳」タブと「③ LINE接続」内の「Webhook連携」カードが増えています

## 手順9: コードを更新するとき

1. エディタでコードを修正して `Ctrl + S`
2. 「デプロイ」→「デプロイを管理」→ 編集（鉛筆アイコン）→ バージョン「新しいバージョン」→「デプロイ」
3. WebアプリのURLは変わりません

## 手順10: Webhookを設定する（Cloudflare Workers）

配布の「README-cloudflare.md」に沿って、署名検証用のWorkerを作成し、
LINE Developersコンソールの「Webhook URL」にWorkerのURLを登録します。
（無料・カード登録不要・所要10分ほど）
その際、GAS側には「全員」アクセスの**Webhook用デプロイをもう1つ作る**必要があります
（README-cloudflare.md の手順C-2.5。管理画面用の「自分のみ」デプロイと併用します）。

完了後の動き:

- 友だち追加 → 「④ 顧客台帳」に自動登録（顧客IDはCU0001形式）
- 友だち解除 → 状態が「解除済み」に変わる（履歴は残る。自動削除はしない方針）
- メッセージ受信 → 「最終反応」日時が更新される（本文は保存しない）
- 既存の友だち → 「④ 顧客台帳」の「既存の友だちを取り込む」ボタンで一括登録

## チャネルアクセストークンの取り扱い（公式ドキュメント確認済み）

- 長期トークンは有効期限なし。LINE Developersコンソールの「Messaging API設定」タブからいつでも発行できる
- 長期トークンを再発行すると、現在使用中の長期トークンは自動的に無効になる
- 漏洩が疑われるときは、コンソールまたはAPIで失効（Revoke）させる
- 本システムではトークンをスクリプトプロパティにのみ保存。シート・画面・ログには一切出力しない
- GASの編集権限を持つ人はスクリプトプロパティを確認できるため、編集者は最小限にする
- WebhookはCloudflare Workerで署名検証してからGASへ渡すため、GASのURLだけ知っていても偽データを送れません（さらに共有キーで二重防護）

## グループ（顧客）へコピーして渡すときのチェックリスト

- [ ] スプレッドシートとGASプロジェクトの所有者は誰か
- [ ] OAuth認可（手順4の承認）を実行したか
- [ ] Webアプリのデプロイ設定（実行ユーザー・アクセス範囲）とURL
- [ ] 手順4で9シートが自動作成されているか
- [ ] LINEチャネルのWebhook URL（手順10でWorkerのURLを設定したか）
- [ ] Cloudflare Workerの変数3つ（CHANNEL_SECRET / GAS_WEBHOOK_URL / GAS_SHARED_KEY）を設定したか
- [ ] グループ間でシート・GAS・Workerが混ざっていないか（別アカウント・別ファイルであること）

※「ファイルをコピーすれば全設定が引き継がれる」わけではないため、毎回この手順書に沿って手動でセットします。

## 付録A: Messaging APIチャネルの作り方（まだチャネルがない場合）

※2024年9月以降の新しい手順です。チャネルは「LINE Official Account Manager」側から作成します（LINE Developersコンソールから直接作る方法は廃止されました。参照: https://developers.line.biz/ja/docs/messaging-api/getting-started/ ）

1. https://account.line.biz/ でLINE公式アカウントを作成（グループ共通の1アカウント）
2. https://manager.line.biz/ にログインし、対象の公式アカウントの「設定」から「Messaging API」の利用を有効にする
3. 有効化するとMessaging APIチャネルが自動で作成されます
4. https://developers.line.biz/console/ を開くと、プロバイダー配下にチャネルが表示されていることを確認します
